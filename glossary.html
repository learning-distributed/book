    Distributed Systems: Principles and Practice

    Glossary

    • Action. The steps taken by a node in response to an event, such as receiving a packet or a timeout expiration. The action may change local state, send messages to other nodes, or set additional timeouts. Cf. Event.

    • Availability. The fraction of time that a system is responsive to requests, including during partial failure events.

    • Cache. A local or nearby copy of partial results or recently used data, designed to reduce the latency of responding to a request.

    • Client. A computer that requests a remote server for some data or for some action to be taken. Cf. Client-server communication.

    • Client-server communication. A common distributed system communication pattern where one node, the client, requests information from or for an action to be taken by another node, the server. Cf. Remote Procedure Call.

    • Cloud computing. Allows companies (and users) to rent computing resources in a shared facility such as a data center, or in many cases, a network of data centers. A common use case is to host the backends of mobile and web applications.

    • Compute Express Link (CXL). A proposed standard for pooling memory between servers in a cache coherent manner.

    • Content distribution network (CDN). A distributed system that aims to place and serve copies of data near to the users that want that data.

    • Core. An individual computational element within a processor, capable of executing instructions and modifying state, with its own local cache.

    • Data center. A place for the centralized computer processing and serving of data.

      • Data center rack. A rack is a set of 40-80 servers, often with a shared network switch and power distribution. Servers within a rack may fail, but sometimes the entire rack can become disconnected if the network switch or power distribution fails.

    • Disaggregated memory/storage. A design pattern where the memory or storage is physically separate from the compute node that uses that memory or storage.

    • Distributed application. A user-facing distributed system, often split between a portion running on the client machine and a portion running on backend servers.

    • Distributed service. A distributed system used by other distributed systems to get their work done.

    • Distributed system. A set of (often geographically) dispersed computers working together to provide some useful service.

    • Event. An occurence on a node in a distributed system that triggers some computation local to the node, such as the arrival of a message or a timeout. Cf. Event Handler.

    • Event handler. The code that runs when an event occurs.

    • Failure. The incorrect functioning of some node or network element in a distributed system.

    • Failure model. A formal description of the types of failures a system is designed to handle.

      • Asynchronous. Tasks in a distributed system, such as to run an event handler or deliver a message, may take an arbitrary amount of time to complete. Cf. Synchronous failure model.

      • Byzantine. The behavior of a failing node or network may be arbitrary, including sending or delivering arbitrary messages. Cf. Fail-stop failure model.

      • Gray. When a node or network continues to operate, but at far below its normal operating parameters. An example is when a network switch or link suddenly starts dropping half of its packets, or if a server needs to perform emergency operating system tasks preventing it from responding for an extended period of time.

      • Fail stop. When a node or network fails, it stops instead of performing incorrectly. Cf. Byzantine failure model.

      • Synchronous. Tasks in a distributed system, such as to run an event handler or deliver a message, always take a bounded amount of time to complete. Cf. Asynchronous failure model.

    • Key-value store. A distributed application that stores values for later key lookup, that is, that provides a function for mapping keys to values.

    • Linearizable. Operations on distributed state are performed as if they occur in a single global order visible to all nodes.

    • Load balancer. A type of microservice that assigns incoming requests to servers.

    • Local state. Memory local to a node. Event handlers can modify local state, but cannot directly modify the state of other nodes.

    • Message. A logical unit of communication between nodes in a distributed system.

    • Microservice. A self-contained distributed system, typically implemented by a single person or a small team, that performs a single well-defined task and is independently scalable. More complex applications and services are composed of operations on a collection of microservices.

    • Network. A group of links and switches that together deliver packets of data from one node to another.

      • Network Link. A means for conveying data from one physical location to another, e.g., from one node to a network switch, between network switches, or from a switch to a node.

      • Network Packet. The physical unit of transfer in a computer network, typically with some defined header format and maximum size.

      • Network Switch/Router. A means for conveying packets between network links in order to move the packet towards the destination. Routers and switches differ based on which part of the packet header is used during forwarding.

    • Network effect. When a system becomes more valuable to each user as a function of how many other people are using the system. A telephone system is an example of the network effect.

    • Node. A computational element in a distributed system that can send and receive messages, read and modify local state, and set and recieve timeouts.

      • Source node. The originating node for a network message.

      • Destination node. The target node for a network message.

    • Partial failure. A failure where some, but not all, of the nodes of a distributed system fail.

    • Peer-to-peer. A communication pattern where clients communicate directly with each other.

    • Planned maintenance. A data center outage for one or many servers, or the networks connecting them, to complete an upgrade. The applications running on those servers can be warned in advance of the outage, e.g., to migrate work onto other servers unaffected by the change, as opposed to a crash fault which happens unexpectedly.

    • Points of presence. Geographically distributed representatives of a distributed system placed near its users.

    • Reliability. The likelihood (ideally very high) that a system performs as intended, that is, it produces the correct result.

    • Quorum. The number of nodes in a distributed system that are consulted before some action is taken, for example, to read or update data. In many distributed systems, the quorum is set to be a simple majority, ensuring that any two quorums intersect with at least one server.

    • Replicated state machine. A model for how multiple servers can implement a fail-stop fault tolerant service by deterministically executing the same sequence of operations in the same order at every replica.

    • REST (Representational State Transfer). A model for building distributed applications with functionality split between a part that runs on each client and a (shared) part implemented as a distributed service. The client may cache data, but stores no persistent state. Instead it transfers the state to the distributed service, simplifying reconnection after an outage.

    • Server. A computer that provides data or takes actions on request. Cf. Client-server communication.

    • Sharding. A parallelization strategy that splits (or shards) the work of a distributed system across a set of servers, for example by assigning different users to different servers.

    • Shrink wrap software. A model for providing software where the software was printed on physical media and shipped to the end user to install.

    • Software as a Service (SaaS). A model for providing software where the software is provided to users by hosting it in the cloud.

    • Stale data. Information about the state of another node may be out of date, or stale, when used on a different machine.

    • Stateful user interaction. A distributed system's behavior depends on both the client request and the server's previous interactions with that and other clients.

    • Timeout. A notification delivered to a node at a specified point in the future.

    • Transaction. A group of operations whose effects are observed as all happening together, or not at all, by other nodes.

    • Trust model. The set of malicious attacks that are addressed, and more importantly not addressed, by a system.
