Style Guide

Style

Headers

All Headers (i.e., #, ##, ### and <h1>, <h2>, <h3> etc.) should be in title case.

Authoring Pages

Content pages should be stored in the src/pages/ directory as .html files. Pages are interpreted using the Jinja templating engine. Every page should extend our base template (or a template that extends our base template) by beginning with 

{% extends "base.html" %}

Pages can optionally begin with "front matter," a section of the file which is interpreted as YAML and made available to the template. For example, starting a page file with 

---
title: Page Title
---
{% extends "base.html" %}
declares the title of the page to be "Page Title".

The base template expects all content to occur in the block named body. This means that every content page should define a body block as follows 

---
title: Page Title
---
{% extends "base.html" %}

{% block body %}
Page content here.
{% endblock %}

Markdown is particularly convenient for writing and reading content. Markdown can be rendered using the {% markdown %} tag as follows 

---
title: Page Title
---
{% extends "base.html" %}

{% block body %}
{% markdown %}

## Markdown header

Mardown content here.

{% endmarkdown %}
{% endblock %}

Comments

Comments in Jinja are written using {# ... #}. Everything inside {# and #} will be ignored by Jinja. HTML style comments written as <!-- ... --> also work but will appear in the output.

Callouts

Callouts are written with:

!!! note
    This is a callout with some useful information.
    The callout can span multiple lines.

    And new paragraphs.

Note

This is a callout with some useful information. The callout can span multiple lines.

And new paragraphs.

The first word becomes the "class" of the call out as well as its title (with the first letter capitalized), and you can optionally override the title with:

!!! note "Callout Title"
    This is a callout with some useful information.

Callout Title

This is a callout with some useful information.

We currently support two special types of callouts: collapsible and todo.

!!! collapsible "Collapsible Callout"
    This callout is collapsible and collapsed by default.

Collapsible Callout

This callout is collapsible and collapsed by default.

!!! todo
    This callout is a TODO.

Todo

This callout is a TODO.

More types can be added as we need them. Custom styles are placed in main.css.

Margin Notes

For now, margin notes are written using HTML divs.

This is a margin note. Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua. 
<div class=marginnote>
This is a margin note.
Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua.
</div>

Margin notes appear wherever in the vertical flow the div appears. Therefore, if you want to add a margin note to a paragraph, you should add it before the paragraph. We don't currently have a good way to add margin notes in the middle of a paragraph. If we have need for this, we can look into adding it in the future.

Also note that margin notes look different depending on the width of the screen. On a smaller screen, they appear inline, but again before the paragraph they're supposed to apply to. We may need to figure out a better way to do this in the future.

References

The BibExtension in build.py provides support for inline citations.

Add entries to references.bib and then cite them like so: 

Lamport introduced the Paxos algorithm as a solution to the
distributed consensus problem {% cite "lamport98:part-time" %}.

If there are any citations on a page, a references section will be automatically added to the end of the page. Currently, works cited will be included in the bibliograph in order of appearance and references are listed on a per-page basis. We can always change this later by changing the base template.

Cross-references

The CrossRefExtension in build.py provides support for labeling and referring to figures etc.

Define a label like this: 

{% label 'fig:style-guide-figure' %}

And then refer to it with: 

{% ref 'fig:style-guide-figure' %}

Both the label and the reference will output something like "Figure 1". The extension is configured to look for a valid "label kind" before the : and will raise an error if it doesn't find one. Currently, the extension only supports fig: but new kinds of labels are easy to add in build.py as we need them.

Labels must only be defined once and all ref tags should refer to defined labels. However, labels can be referred to before they are defined.

The extension does not yet support cross-file references. Support for that is coming.
